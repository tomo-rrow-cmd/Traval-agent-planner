## 待澄清清单

1. `docs/originals/` 目前保留技术架构、数据库设计、团队报告和项目优先级等原始文件，未看到独立"需求设计"原始文档。是否还会补充需求文档？
2. ✅ **已解决（D-014/D-015/D-024）**：V1.0 已实现手机号注册、验证码/密码登录、刷新 Token 和登出；开发态短信验证码固定为 `123456`。
3. ✅ **已解决（D-044）**：当前仓库已确认前后端单仓，Web 客户端（Vue 3）和 Android 客户端（Kotlin + Jetpack Compose）同时开发；小程序排到后续版本。
4. ✅ **已解决（D-020/D-044）**：仓库采用前后端单仓，后端根目录为 `app/`，Web 客户端为 `frontend/`，Android 客户端为 `android/`。
5. Node.js（≥18）、PostgreSQL、Redis 的精确版本是否需要锁定到项目配置中？当前仅 Python 3.12 已锁定（D-018）。
6. ✅ **已解决（D-005 实践收敛）**：当前主模型为 DeepSeek，豆包和通义千问保留为备选适配器，通过统一 LLM 服务层切换。

8. 初始城市和基础数据范围是什么？例如只支持中国热门城市，还是需要境外目的地？
9. 景点、餐厅、酒店、纪念品基础数据从哪里来？人工维护、第三方 API、爬虫、公开数据集还是混合方案？
10. 是否需要真实地图路线规划，还是 V1.0 只需要基于距离和时间估算的路线建议？
11. ✅ **已解决（D-036）**：方案导出格式已确认支持 Markdown（同步）、PDF/PNG/DOCX（异步任务 + 下载）。
12. 方案分享是否公开可访问？是否需要访问密码、过期时间、撤销分享能力？
13. ✅ **已解决（D-024）**：V1.0 认证方式为手机号 + 验证码/密码；微信 OAuth 未进入当前迭代。
14. 内容安全审核在 V1.0 是否必须接入真实服务，还是先保留接口并使用 Mock/规则审核？
