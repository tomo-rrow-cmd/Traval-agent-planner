# 三、技术选型详解

## 3.1 后端技术栈

### 3.1.1 FastAPI Web框架

FastAPI是一个现代、快速（高性能）的Python Web框架，基于标准Python类型提示。

核心特性：

高性能：基于Starlette和Pydantic，性能接近Node.js和Go

自动文档：自动生成Swagger UI和ReDoc接口文档

类型安全：基于Python类型提示，IDE支持好，减少Bug

异步原生：原生支持async/await，高并发性能好

依赖注入：强大的依赖注入系统，便于代码复用和测试

在本项目中的应用：

提供RESTful API接口

接口参数校验和响应序列化

WebSocket流式输出支持

依赖注入管理数据库会话、用户认证等

### 3.1.2 Pydantic数据校验

Pydantic是Python中最流行的数据校验库，FastAPI深度集成。

核心用途：

请求参数校验：自动校验接口入参的类型、格式、范围

响应模型定义：定义接口返回的数据结构

配置管理：基于Pydantic Settings的类型安全配置

智能体输入输出：定义各智能体的标准化数据结构

### 3.1.3 SQLAlchemy ORM

SQLAlchemy是Python生态最成熟的ORM框架，2.0版本全面支持异步。

核心特性：

异步支持：使用asyncpg驱动，全异步数据库操作

类型安全：支持Mapped类型提示，IDE友好

关系映射：完善的一对多、多对多关系映射

查询优化：支持懒加载、预加载、N+1问题优化

迁移工具：配合Alembic做数据库版本管理

### 3.1.4 项目分层架构

后端项目采用经典的分层架构：

API层（api/）：接口定义、参数校验、响应封装

Service层（services/）：业务逻辑封装、原子能力实现

Agent层（agents/）：智能体实现、工具集封装

Orchestrator层（orchestrator/）：多智能体编排、工作流管理

DAO层（db/）：数据库模型、数据访问封装

Schema层（schemas/）：Pydantic数据模型定义

Utils层（utils/）：通用工具函数、日志、缓存等

## 3.2 AI/Agent技术栈

### 3.2.1 LangGraph多智能体编排

LangGraph是LangChain团队推出的多智能体编排框架，基于有向图和状态机设计，专门用于构建复杂的、有状态的多智能体系统。

核心概念：

State（状态）：全局共享的状态对象，所有节点都可以读取和修改

Node（节点）：工作流中的每个处理单元，可以是一个函数或一个Agent

Edge（边）：节点之间的连接关系，支持条件边和分支

Graph（图）：由节点和边组成的工作流，支持循环、分支、子图

在本项目中的应用：

构建旅行规划工作流：信息收集 → 并行规划 → 冲突检测 → 路线优化 → 方案整合

管理规划全流程状态：需求信息、中间结果、最终方案

支持条件分支：信息不足时追问，信息充足时继续规划

支持循环重试：智能体失败时自动重试，多次失败则降级

### 3.2.2 LangChain工具链

LangChain提供了丰富的工具和组件，用于构建LLM应用。

核心组件：

LLM集成：统一的大模型调用接口，支持多家模型切换

Tool封装：标准的工具封装格式，支持Function Calling

Prompt模板：灵活的Prompt模板管理，支持变量替换

输出解析器：将LLM输出解析为结构化数据

向量检索：RAG知识库检索能力

### 3.2.3 大语言模型

主力模型：字节豆包 Doubao-Pro-32K

上下文窗口：32K Token，足够处理复杂的规划任务

中文效果：对中文理解和生成效果优秀

Function Calling：支持稳定的工具调用

成本：价格适中，性价比高

备选模型：通义千问 Qwen-Turbo

作为备用模型，主模型故障时自动切换

简单任务使用，降低成本

模型分层策略：

简单对话、信息提取：使用轻量模型，降低成本

方案生成、内容润色：使用主力模型，保证效果

复杂推理、质量优化：使用高级模型（可选）

### 3.2.4 Prompt工程体系

建立完善的Prompt管理体系，保证Prompt的可维护性和可迭代性。

Prompt分类：

系统Prompt：定义智能体的角色、职责、输出格式、约束规则

任务Prompt：具体任务的指令和要求

工具Prompt：工具调用的描述和参数说明

优化Prompt：结果润色、质量提升的指令

Prompt管理原则：

独立文件存储，不硬编码在代码中

版本管理，每次变更都有记录

A/B测试，数据驱动优化

按智能体分类，便于维护

## 3.3 数据库技术栈

### 3.3.1 PostgreSQL关系数据库

PostgreSQL是一款功能强大的开源关系型数据库，以其可靠性、数据完整性和正确性著称。

选型理由：

JSON支持：原生支持JSONB类型，适合存储半结构化的方案数据

地理信息：PostGIS扩展提供强大的地理信息处理能力

全文检索：内置全文检索功能，支持景点、餐厅等模糊搜索

事务支持：完善的ACID事务支持，保证数据一致性

性能优异：查询优化器强大，复杂查询性能好

在本项目中的核心表：

用户表（users）：存储用户信息、偏好配置

会话表（sessions）：存储对话会话、规划状态

方案表（plans）：存储生成的旅行方案

景点表（attractions）：景点基础信息库

餐厅表（restaurants）：餐厅基础信息库

酒店表（hotels）：酒店基础信息库

城市字典表（cities）：城市基础数据

操作日志表（operation_logs）：用户操作记录

### 3.3.2 Redis缓存数据库

Redis是一个高性能的内存数据库，用作缓存和会话存储。

核心用途：

热点数据缓存：热门城市的景点、餐厅、酒店数据缓存

会话状态存储：用户会话、规划过程中的临时状态

接口限流：API接口限流计数，防止恶意请求

分布式锁：防止重复生成方案、并发操作冲突

消息队列：异步任务队列，方案生成异步处理

缓存策略：

基础数据（景点、餐厅、酒店）：缓存24小时，定时更新

用户会话：缓存7天，用户活跃自动续期

方案结果：缓存30天，用户可随时查看

第三方API结果：按API特性设置不同缓存时间

### 3.3.3 向量数据库

向量数据库用于存储和检索向量嵌入，支持语义搜索和RAG。

选型：Chroma（V1.0）→ Milvus（V2.0）

V1.0使用Chroma，轻量易用，部署简单，适合初期

V2.0数据量大后迁移到Milvus，性能更好，支持大规模

核心用途：

景点语义搜索：根据用户描述推荐相似景点

美食语义搜索：根据口味偏好推荐餐厅

知识库检索：旅游攻略、避坑指南等知识库的语义检索

用户画像匹配：根据用户偏好匹配最适合的方案

### 3.5.1 高德地图API

核心接口：

地理编码/逆地理编码：地址与经纬度互转

路径规划API：驾车、公交、步行、骑行路线规划

POI搜索：关键字搜索、周边搜索、多边形搜索

距离测量：两点间距离、多点距离矩阵

行政区划：城市编码、区域边界

使用策略：

基础数据批量拉取，缓存到本地数据库

实时路径规划调用API，结果短期缓存

配置限流和降级，超出配额时使用备用方案

### 3.5.2 和风天气API

核心接口：

城市天气查询：实时天气、7天预报、逐小时预报

空气质量：AQI指数、污染物浓度

生活指数：穿衣、紫外线、运动、旅游等指数

灾害预警：天气灾害预警信息

### 3.5.3 第三方服务接入原则

统一封装：所有第三方服务都封装为内部服务，屏蔽外部差异，便于切换

主备双活：每个核心服务至少有一个备选方案，主服务故障自动切换

缓存优先：能缓存的尽量缓存，减少API调用，降低成本，提升性能

限流熔断：配置限流和熔断机制，防止第三方服务故障影响自身系统

成本控制：监控API调用量，设置预算告警，控制成本
