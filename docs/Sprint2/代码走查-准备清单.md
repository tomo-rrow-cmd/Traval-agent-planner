> 
> **交叉Review时间**：7月15日上午（见 Sprint 2 阶段验收 要求.md 第二部分）

---

## 交叉Review 流程回顾

```
第一步（A组准备，20分钟）→ 第二步（质询会，15分钟）→ 第三步（老师评价，3分钟）
```

A组提问需覆盖三类问题：
- **"为什么"类**：为什么这里用这个方案而不是另一个？
- **"如果"类**：如果需求变成XXX，这段代码哪里会出问题？
- **"我没看懂"类**：哪段代码读不懂，请作者解释

## 今日预演建议

每人从自己负责的模块中挑 2-3 个"亮点"，想清楚：

1. **为什么这样写** — 当时的决策理由是什么？（用AI辅助做这个决策了吗？利弊是什么？）
2. **如果需求变了会怎样** — 比如目的地从国内变海外、预算减少50%、行程从5天变30天
3. **最好懂但也可能被问住的点** — 主动准备比被动应对好

## 明天Review产出的模板

审查完需出具"简短报告（3-5条建议）"给被审查组。建议用以下格式：

```markdown
# 交叉Review报告 — [A组→B组]
审查人: [姓名]
审查时间: 2026-07-15

## 发现的问题

1. **[问题类别]**：[文件名:行号]
   - 现象：[描述]
   - 风险：[安全隐患/可维护性/性能/...]
   - 建议：[具体修改方案]

2. ...

## 亮点（可选）
- [值得肯定的代码实践]
```
