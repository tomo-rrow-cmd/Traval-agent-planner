## 场景一：并发幂等性 — 重复消息去重

| 维度 | 说明 |
|------|------|
| **场景分类** | 并发 / 竞态条件 |
| **极端输入** | 8 个并发请求携带**完全相同**的 `client_message_id` |
| **预期行为** | 仅创建 **1 条**消息记录，其余 7 条返回已有记录（幂等回放标记 `_idempotent_replay=True`），不产生重复数据 |
| **测试函数** | `test_concurrent_duplicate_client_message_id_creates_one_message` |
| **代码位置** | [tests/test_conversation_postgres.py](../../tests/test_conversation_postgres.py) |
| **测试结果** | ✅ 通过 |
| **是否已修复** | N/A（设计即如此） |

**输入示例**：
```python
# 8 个协程并发调用，全部携带相同的 client_message_id="msg-dup-1"
await asyncio.gather(*[
    record_message(conversation_id, "Hello", "msg-dup-1")
    for _ in range(8)
])
# → 数据库仅 1 条记录，其余 7 条 idempotent replay
```

## 场景二：硬上限裁剪 — 单日景点数超限

| 维度 | 说明 |
|------|------|
| **场景分类** | 硬上限 / 数据裁剪 |
| **极端输入** | 一天安排了 **5 个景点**（系统硬上限为 **4 个**） |
| **预期行为** | 确定性裁剪到 `attractions[:4]`，**不调用 LLM**（`auto_trimmed=True`, `decision_needed=False`），保证结果可复现 |
| **测试函数** | `test_decision_round1_deterministically_trims_overfull_day` |
| **代码位置** | [tests/test_agents.py](../../tests/test_agents.py) |
| **测试结果** | ✅ 通过 |
| **是否已修复** | N/A（硬编码阈值，AI 不可修改，见 `.agent/guardrails.md`） |

**输入示例**：
```python
day = {
    "attractions": ["故宫", "天坛", "颐和园", "长城", "鸟巢"],  # 5个 → 超出
    "meals": [{"type": "lunch", "name": "烤鸭"}]
}
# → attractions 裁剪为 ["故宫", "天坛", "颐和园", "长城"]
# → auto_trimmed=True, decision_needed=False
```

**关联边界测试**：`test_decision_round1_preserves_boundary_and_matches_meals` 验证恰好 4 个（边界值）的场景——day1 保持原样，day2 被裁剪，meals 正确匹配。

## 场景三：事务原子性 — 持久化部分失败回滚

| 维度 | 说明 |
|------|------|
| **场景分类** | 事务 / 部分失败 |
| **极端输入** | 持久化流程的 **3 个关键步骤** 分别注入失败：① run 写入失败 ② status 更新失败 ③ message 写入失败 |

| **代码位置** | [tests/test_services.py](../../tests/test_services.py) |
| **测试结果** | ✅ 通过 |
| **是否已修复** | N/A（事务边界设计保证） |

**输入示例**：
```python
# parametrize: fail_at ∈ {"run", "status", "message"}
# 注入：对应 repository 方法 raise RuntimeError
persist_plan_result(plan, conversation_id)
# → 抛出异常，db.commit() 未被调用
```

## 场景四：极端外部数据 — 爬虫返回异常价格

| **代码位置** | [tests/test_agents.py](../../tests/test_agents.py) |
| **测试结果** | ✅ 通过 |
| **是否已修复** | N/A（Agent 内置异常价格 fallback 逻辑） |

**输入示例**：
```python
# Meituan parser 返回
hotel_data = {"price_per_night": 1, "name": "测试酒店"}
budget = {"hotel_budget": 500}
nights = 2
# → price_verified=False, estimated=True
# → price_per_night=500 (fallback), total=1000
```

## 场景五：缺失必填字段 — 用户信息不完整

| **代码位置** | [tests/test_agents.py](../../tests/test_agents.py) |
| **测试结果** | ✅ 通过 |
| **是否已修复** | N/A（UserInteractionAgent 内置必填字段校验） |

**输入示例**：
```python
user_input = "我想去云南昆明玩5天"
# 有 destination="云南昆明", days=5
# 缺 origin, total_budget, preferences
```

## 补充：硬编码业务阈值（AI 禁飞区）

以下阈值定义在 `.agent/guardrails.md` 中，AI 不可修改，由确定性代码强制：

| 文件 | 阈值 | 说明 |
|------|------|------|
| `decision_agent.py::run_round1()` | `attractions[:4]` | 每天最多 4 个景点 |
| `validator.py::validate_budget()` | `per_person_per_day < 100` | 最低预算下限 |
| `validator.py::validate_date_range()` | `days > 30` | 行程最长 30 天 |
| `validator.py::validate_date_range()` | `start < date.today()` | 不能早于今天 |
| `validator.py::validate_date_range()` | `end < start` | 结束日期 > 开始日期 |
| `traffic_agent.py::_route_stops()` | Lunch ≤ 14:00, Dinner ≤ 21:00 | 用餐时间约束 |
| `budget_agent.py::_adj()` | `hotel_budget >= 200`, `meal_budget >= 50` | 预算调整下限 |
| `budget_agent.py::run()` | `0 < over_pct <= 30 and retry < 2` | 预算重试熔断器 |
