## 三、仍需注意的问题

### 3.1 Pipeline 性能问题

| 问题 | 影响 | 说明 |
|------|------|------|
| 规划管线耗时 60~80 秒 | ⚠️ 用户需长时间等待 | 4 个 Agent 串行调用 DeepSeek LLM，每个约 20s。parallel_planning 虽并发 3 个 Agent，但 LLM 响应慢是瓶颈 |
| 规划期间无实时进度反馈 | ⚠️ 用户感知卡死 | step_start 发出后，parallel_planning 阶段无中间进度事件，前端仅显示动画圆点 |
| 无超时熔断机制 | ⚠️ 极端情况可能无限挂起 | DeepSeekLLM 已加 timeout=60，但 Agent 重试 3 次可能导致最长 180s |

### 3.2 数据质量问题

| 问题 | 影响 | 说明 |
|------|------|------|
| 向量搜索用伪随机向量 | ⚠️ 景点推荐排序无意义 | sentence_transformers / modelscope 未安装，rebuild_vectors --allow-pseudo 生成随机向量 |
| 酒店价格全为 0 | ⚠️ 预算计算不准确 | 高德 POI 不返回价格，seed_poi.py 未拉取到 |
| 部分景点分类不当 | ⚠️ 推荐不够精准 | seed 只搜索了风景名胜/博物馆/公园广场等分类，缺少文化遗产/历史建筑等 |
| 12306 站点名称为内部代码 | ⚠️ 显示难读 | 返回 fromStation: GBA, toStation: BXP 而非广州/北京 |
| 同一酒店重复多天 | ⚠️ 体验差 | 候选酒店只有 2 家，LLM 反复推荐同一家 |

### 3.3 高德 API Key 问题

| 问题 | 影响 | 说明 |
|------|------|------|
| API Key 平台不匹配 | ⚠️ USERKEY_PLAT_NOMATCH | 当前 Key 是 Web JS Key（前端用），seed_poi.py 需要 Web 服务 Key（服务器 HTTP 用） |
| 地理编码服务报错 | ⚠️ 坐标查询失败 | geocode/geo 返回 ENGINE_RESPONSE_DATA_ERROR |
