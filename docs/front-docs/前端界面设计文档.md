## 一、页面架构与路由设计

### 1.1 路由表

| 路由路径 | 页面名 | 访问控制 | 说明 |
|----------|--------|---------|------|
| `/` | HomePage | 公开 | 品牌展示、快速开始入口 |
| `/chat` | ChatPage | 登录/匿名 | 对话式需求收集与方案生成 |
| `/chat/:sessionId` | ChatSessionPage | 登录/匿名 | 指定会话的对话页 |
| `/plans` | PlanListPage | 登录 | 用户已保存的方案列表 |
| `/plans/:planId` | PlanDetailPage | 登录 | 单方案完整展示（含内联修改面板） |
| `/profile` | ProfilePage | 登录 | 个人资料与偏好设置 |
| `/profile/preferences` | PreferencePage | 登录 | 详细偏好配置面板 |
| `/login` | LoginPage | 未登录 | 手机号登录 |
| `/register` | RegisterPage | 未登录 | 注册页 |
| `/404` | NotFoundPage | 公开 | 404 兜底 |

**变更说明**（相对初版）：
- 删除了独立的 `/plans/:planId/edit` 路由。方案修改统一在 **PlanDetailPage 内联抽屉** 中完成——点击任一 ActivityItem 的"替换"按钮，弹出底部/侧边抽屉展示候选列表，选择后触发 modification SSE 流局部更新。无需导航到独立编辑页，避免上下文切换。

**路由规范**：
- 路径一律使用 `kebab-case`
- 匿名用户仅限访问 `/` 和 `/chat`（以匿名会话方式使用），触发方案保存时提示登录
- 登录用户访问受保护页如未登录，自动重定向至 `/login?redirect=原路径`
- 所有路由在 `src/router/index.ts` 集中配置

### 1.2 路由守卫策略

```
路由导航
  ├── 公开路由（/ /login /register）：不做拦截
  ├── 匿名可用（/chat /chat/:sessionId）：无 token 创建匿名会话
  └── 登录保护（/plans /profile 等）：无 token 重定向 /login?redirect=当前路径
```

- 使用 Vue Router 的 `beforeEach` 全局守卫
- 登录状态通过 `authStore.isLoggedIn` 判断
- 匿名会话标识（`X-Session-Id`）存储在 sessionStorage 中，登录后合并

### 1.3 匿名用户边界

| 场景 | 行为 |
|------|------|
| 访问 `/chat` | 自动创建匿名会话，可输入需求和生成方案 |
| 方案生成完成 | 方案存入后端匿名上下文，前端显示"保存方案需登录"提示条 |
| 点击"保存" | 跳转 `/login?redirect=/plans/:planId` |
| 登录后 | 调用 `mergeAnonymousData()` 合并匿名会话数据和方案到用户账号 |

## 二、布局体系

### 2.1 布局层级

```
AppLayout（根布局壳）
├── PublicLayout          # 登录/注册/首页 — 简洁裸露布局
│   └── <router-view>
├── AuthLayout            # 需登录页面 — 含侧栏/顶栏
│   ├── AppSidebar        # 导航侧栏（会话列表、方案入口）
│   ├── AppHeader         # 用户头像、通知、设置入口
│   └── <router-view>
└── PlanLayout            # 方案详情专用布局 — 全宽、沉浸式
    ├── AppHeader（简洁版）
    └── <router-view>
```

### 2.2 布局组件职责

| 组件 | 职责 |
|------|------|
| `AppLayout.vue` | 根布局壳，初始化用户会话、主题、全局异常捕获；提供路由插槽 |
| `PublicLayout.vue` | 居中单栏布局，用于登录/注册/首页，无侧栏干扰 |
| `AuthLayout.vue` | 左侧侧栏 + 右侧主内容区，侧栏显示最近会话列表（类似 ChatGPT 侧栏），顶部显示用户信息 |
| `PlanLayout.vue` | 纯内容沉浸式布局，最大化方案呈现空间，顶部为简洁版 AppHeader |

### 2.3 侧栏（AppSidebar）设计

- 新会话按钮 -> 触发 `POST /chat/sessions` 并跳转
- 最近会话列表 -> 按更新时间倒排，显示会话标题/预览
- 会话项支持右键/长按 -> 重命名、删除
- 底部固定 -> "我的方案"入口 + 用户菜单
- 折叠状态由 `uiStore.sidebarCollapsed` 控制
- 组件命名统一为 `AppSidebar.vue`（不再使用 `SidebarNav.vue`）

### 3.2 组件复用原则

| 原则 | 说明 |
|------|------|
| **Ant Design Vue 优先** | 表格、表单、按钮、弹窗、消息提示、步骤条等通用 UI 直接使用 Ant Design Vue 组件，不自封装 |
| **common/ 跨页面复用** | `common/` 下为基础组件，任何页面/组件均可引用 |
| **领域内复用** | `chat/`、`plan/`、`preference/`、`notification/` 下的组件只在其所属领域内复用，不允许跨域引用 |
| **地图统一封装** | `MapContainer.vue` 统一封装高德地图 JS API 加载、实例管理、销毁清理；所有使用地图的页面只通过该组件接入 |
| **页面级组件就近放** | 只在单个页面使用的组件放在 `views/<page>/components/` 下 |

### 3.3 组件通信原则

- **父子组件**：props 向下传递数据，emit 向上通知事件
- **跨组件**：通过 Pinia Store 共享状态，不通过事件总线或 provide/inject 跨域传递
- **SSE 数据**：统一由 `chatStore` 管理 EventSource，解析后写入 `planStore`

## 四、核心交互流程

### 4.1 方案生成主流程

```
用户进入 /chat
  → 系统自动创建会话（POST /api/v1/chat/sessions）
  → 显示空对话界面
  → 用户输入："我想去大理玩3天"
  → POST /api/v1/chat/send { session_id, content }
  → 后端返回 SSE 流：
      - step_start: "info_collection"    → UI 显示"正在了解您的需求..."
      - progress: "正在追问出行人数..."  → UI 更新追问气泡
      - 用户回答追问，继续 SSE
      - step_start: "parallel_planning"  → UI 显示"正在并行规划..."
      - progress: "30% 景点筛选完成"
      - progress: "60% 交通方案对比中"
      - step_end: "planning_complete"
      - done: { plan_id }               → UI 跳转方案详情页
```

**UI 阶段状态机**：

| 状态 | UI 呈现 | 说明 |
|------|---------|------|
| `idle` | 空对话界面 + 欢迎语 | 等待用户输入 |
| `collecting` | AI 追问卡片 + 快捷选项按钮 | 信息收集阶段 |
| `planning` | 进度条 + 步骤描述 + 各模块状态 | 并行规划阶段 |
| `completed` | 方案结果消息 + "查看详情"按钮 | 生成完成，自动跳转或点击跳转 |
| `error` | 错误提示 + 重试按钮 | 生成失败 |

### 4.2 方案详情页交互

```
PlanDetailPage 布局
├── PlanHeader        # 目的地、日期、预算概要
│   └── 操作按钮组：[收藏] [分享] [导出 ▼] [编辑]
├── PlanTimeline      # 水平时间线导航（D1 / D2 / D3 ...）
├── 主体区（两栏）
│   ├── 左栏 / 上栏：DayCard × N（每次只展开一个）
│   │   └── 每个 DayCard 内：
│   │       ├── 日期头（日期 + 天气概要 + 日花费）
│   │       ├── ActivityItem 列表（按时间顺序）
│   │       │   ├── 类型图标 + 时间区间 + 标题
│   │       │   ├── 展开详情（描述、费用、评分、贴士）
│   │       │   └── 操作：[替换] [删除]（V1.0 内联抽屉；V2.0 拖拽排序）
│   │       ├── 交通衔接提示
│   │       └── 住宿卡片
│   └── 右栏 / 下栏：PlanMap（地图标注当天活动）
├── BudgetChart       # 预算饼图（ECharts）
└── BudgetDetailTable # 预算明细表
```

**交互要点**：

- **时间线导航**：固定在页面顶部，随滚动高亮当前天；点击某天 → 对应 DayCard 滚动展开
- **DayCard**：可折叠/展开；同一时间只有一个 DayCard 处于展开状态
- **地图联动**：默认显示当天路线 POI 标注；点击时间线其他天切换地图显示；点击地图标记 → 弹出 POI 详情卡片
- **替换操作**（V1.0 唯一修改入口）：点击 ActivityItem 上的"替换" → 弹出 `ActivityDrawer` 底部抽屉 → 显示至多 5 个候选 → 选择后触发 modification SSE 流 → 局部更新 DayCard 和地图
- **拖拽排序**（V2.0）：ActivityItem 支持拖拽调整顺序，V1.0 暂不支持
- **展开详情**：点击 ActivityItem 行展开/收起详情信息

### 4.3 方案局部修改流程

```
用户在 PlanDetailPage 点击某活动的"替换"
  → 弹出 ActivityDrawer 底部抽屉
  → 显示候选列表（基于原偏好重新推荐，至多 5 个选项）
  → 用户选择新活动项
  → POST /api/v1/plans/{planId}/modify { modifications: [...] }
  → SSE 返回局部优化进度
      - step_start: "modifying"
      - progress: "正在调整行程..."
      - step_end: "modify_complete"
      - done: { plan_id, updated_sections: ["day_1"] }
  → 前端仅更新有变更的 DayCard 和地图内容（非全页刷新）
  → ActivityDrawer 自动关闭
  → 局部更新完成后在 DayCard 右上角显示"已更新"徽标 2 秒
```

**自动保存策略**：

| 控件类型 | 防抖策略 | 保存反馈 |
|---------|---------|---------|
| 滑块（BudgetSlider） | 拖拽停止后 500ms 防抖 | 保存中显示加载指示器，保存成功后显示 ✓ 图标 2 秒，失败显示 ⚠️ + "保存失败" |
| 标签组（DietTagGroup） | 选择/取消后立即触发 | 同上 |
| 文本输入（AI 助手名称） | 停止输入后 800ms 防抖 | 同上 |
| 开关（午休） | 切换后立即触发 | 同上 |

- **离线保护**：偏好变更触发保存前优先写入 localStorage，网络恢复后自动同步
- **保存失败**：显示 `InlineAlert` 提示"偏好保存失败，将在网络恢复后重试"，并自动排队重试 3 次
- **默认加载**：新会话自动加载偏好作为默认值
- **会话内覆盖**：允许在对话中临时覆盖偏好，不影响已保存默认值

### 4.5 导出与分享流程

**导出**：
```
点击"导出 ▼"下拉菜单
  ├── 📄 导出为 PDF      → POST /api/v1/plans/{planId}/export 异步任务 → 轮询/等待 → 文件下载
  ├── 🖼️ 导出为图片      → 同上
  ├── 📝 导出为 Markdown → 同上（同步返回，直接下载）
  └── 📄 导出为 Word     → POST /api/v1/plans/{planId}/export?format=docx → 异步任务
```

| 格式 | 同步/异步 | 说明 |
|------|----------|------|
| `md` | 同步 | 服务端即时生成，直接返回文件 |
| `pdf` / `image` / `docx` | 异步 | 先返回 `task_id`，前端轮询任务状态，完成后下载 |

异步导出流程：
```
点击导出
  → POST /api/v1/plans/{planId}/export?format=pdf
  → 返回 { task_id: "task_xxx", status: "processing" }
  → 前端用 GET /api/v1/tasks/{taskId} 轮询状态（每 2 秒，最多 30 次）
  → status === "completed" → 触发文件下载
  → status === "failed"    → 显示错误提示 + 重试按钮
```

**分享**：
```
点击"分享"按钮
  → 弹出 ShareDialog
  → 设置：过期时间（可选，预设 1天/3天/7天/30天）、访问密码（可选）
  → 点击"生成分享链接"
  → POST /api/v1/plans/{planId}/share { expire_in?, password? }
  → 显示分享 URL + 复制按钮 + 分享到微信/朋友圈快捷入口
```

## 五、SSE 重连策略

### 5.1 连接生命周期

```
建立连接 → 接收事件 → 连接断开 → 指数退避重连 → 达到上限 → 通知用户
                          ↓
                    新的 session 恢复 → 通过 GET /chat/stream/{sessionId} 重新连接
```

### 5.2 重连参数

| 参数 | 值 | 说明 |
|------|------|------|
| 初始重连延迟 | 1 秒 | 第一次断连后等待 1 秒重试 |
| 退避策略 | 指数退避 | 1s → 2s → 4s → 8s → 16s → 30s（封顶） |
| 最大重试次数 | 10 次 | 超过 10 次后停止自动重连 |
| 心跳 | 服务器每 30 秒发送 `: keepalive` 注释行 | 客户端超时 45 秒未收到任何数据即判定断开 |
| Last-Event-ID | 客户端记录最后一个事件的 ID | 重连时在 Header 中携带，服务端从断点续传 |

### 5.3 前端实现

```typescript
// chatStore 中的 SSE 管理
actions: {
  connectStream(sessionId: string): void {
    const lastId = this.lastEventId  // localStorage 缓存的最后事件 ID
    const url = `/api/v1/chat/stream/${sessionId}`
    const headers = lastId ? { 'Last-Event-ID': lastId } : {}
    
    this.eventSource = new EventSource(url, { headers })
    this.retryCount = 0
    
    this.eventSource.onopen = () => { this.retryCount = 0 }
    this.eventSource.onerror = () => { this.handleReconnect(sessionId) }
  },
  
  handleReconnect(sessionId: string): void {
    this.retryCount++
    if (this.retryCount > 10) {
      this.isStreaming = false
      uiStore.showToast({ type: 'error', message: '连接已断开，请刷新页面重试', duration: 0 })
      return
    }
    const delay = Math.min(1000 * Math.pow(2, this.retryCount - 1), 30000)
    setTimeout(() => this.connectStream(sessionId), delay)
  }
}
```

### 5.4 心跳超时兜底

- 客户端启动一个 45 秒计时器，收到任何 SSE 事件（包括 `: keepalive`）时重置
- 45 秒内无事件触发，判定连接断开，进入重连流程
- 页面可见性变化（切后台/返回）时重置计时器

## 六、状态管理与数据流

### 6.1 Pinia Store 设计

```
src/store/
```

### 6.2 Store 详细职责

#### authStore

```typescript
// 状态
state: {
  user: UserProfile | null
  accessToken: string | null
  refreshToken: string | null
  expiresIn: number  // access token 过期时间戳
  isLoggedIn: boolean
  isAnonymous: boolean
  anonymousSessionId: string | null  // 匿名会话 ID

// 关键动作

  loginWithPhone(phone: string, code: string): Promise<void>
  loginWithWechat(code: string): Promise<void>
  refreshToken(): Promise<void>
  logout(): void
  createAnonymousSession(): string  // 返回 sessionId

```

**匿名数据合并流程**：
1. 用户以匿名身份生成方案 → 方案存在后端匿名上下文中
2. 用户登录 → 前端调用 `POST /api/v1/user/merge-anonymous { anonymous_session_id }`
3. 后端将该匿名会话产生的所有方案转移到用户账号下
4. 前端刷新方案列表，显示合并后的数据

#### uiStore

```typescript
// 状态
state: {
  sidebarCollapsed: boolean
  theme: 'light' | 'dark'
  globalLoading: boolean
  currentBreakpoint: 'xs' | 'sm' | 'md' | 'lg'
  toasts: Toast[]          // 通知列表
  onlineStatus: boolean    // 网络连接状态
}

// 通知类型
interface Toast {
  id: string
  type: 'success' | 'error' | 'warning' | 'info'
  message: string
  description?: string
  duration: number         // 自动关闭时间（ms），0 表示不自动关闭
  action?: {
    label: string          // 按钮文字，如"查看详情"
    handler: () => void    // 点击回调
  }
  createdAt: number
}

// 关键动作
actions: {
  toggleSidebar(): void
  setTheme(theme: 'light' | 'dark'): void
  showToast(toast: Omit<Toast, 'id' | 'createdAt'>): string  // 返回 toast id
  dismissToast(id: string): void
  dismissAllToasts(): void
}
```

**通知自动关闭时长**：

| 类型 | 默认时长 | 说明 |
|------|---------|------|
| `success` | 3 秒 | 操作成功提示 |
| `info` | 5 秒 | 一般信息提示 |
| `warning` | 8 秒 | 警告提示 |
| `error` | 0（不自动关闭） | 错误提示，需用户手动关闭 |

**通知持久化**：方案生成完成等关键通知，即使用户在其他页面，也通过 `showToast` 推送到全局通知容器中；用户可点击通知跳转至目标页面。

### 6.3 数据流原则

```
API 响应 → Store Action → Store State → 组件响应式消费
```

| 原则 | 说明 |
|------|------|
| **单向数据流** | 组件不直接修改 API 返回值，所有数据变更通过 Store Action 驱动 |
| **SSE 流管理** | `chatStore` 统一管理 EventSource 生命周期；解析事件后写入 `planStore` 进度/方案字段 |
| **局部更新** | 方案修改完成后只更新有变更的 `day` 数据，不重新请求完整方案 |
| **偏好合并** | `getEffectivePreferences()` 合并持久化偏好与会话临时覆盖值 |
| **缓存策略** | 方案列表内存缓存 5 分钟；基础数据 localStorage 缓存 24 小时；地图瓦片由高德 SDK 自管理 |
| **离线优先** | 偏好修改先写入 localStorage，网络恢复后同步到服务端 |

### 8.5 地图组件设计（MapContainer.vue）

#### 8.5.1 生命周期管理

```
挂载
  ├── 检查高德 SDK 是否已加载
  ├── 未加载 → 动态创建 <script> 标签加载 JS API
  │   ├── 加载成功 → 初始化地图实例
  │   └── 加载失败（超时 10 秒）→ 显示 fallback UI
  └── 已加载 → 直接初始化地图实例
      ├── 设置中心点、缩放级别
      ├── 绑定事件（click、marker_click）
      └── 发射 ready 事件

更新（props 变化）
  ├── 清空并重新添加 Marker 和 Polyline
  └── 飞行动画到新的中心点

卸载
  ├── 销毁所有覆盖物（Marker、Polyline、InfoWindow）
  ├── 调用 map.destroy() 销毁地图实例
  └── 移除事件监听
```

#### 7.5.2 失败 fallback

```
加载失败（CDN 被墙/超时）
  → 显示内置 fallback 区域
  ├── 显示静态地图截图（如果有）
  └── 显示文字标注列表 + "地图加载失败"提示
  └── 提供"重新加载"按钮
```

#### 7.5.3 多实例策略

- 默认全局只维护一个地图实例（在 PlanDetailPage 中）
- 如果特殊场景需要多个地图共存，通过 `MapContainer` 的 `instanceId` prop 区分
- 每个实例使用独立的 AMap 对象，互不干扰

## 十、通知与反馈体系

### 10.1 通知类型与展现

| 类型 | UI 组件 | 展现位置 | 自动关闭 | 用户操作 |
|------|---------|---------|---------|---------|
| `success` | `ToastItem`（绿） | 页面右上角 Toast | 3 秒 | 可主动关闭 |
| `info` | `ToastItem`（蓝） | 页面右上角 Toast | 5 秒 | 可主动关闭，可配置 action Button |
| `warning` | `InlineAlert` + `ToastItem`（黄） | 页面顶部 + 右上角 | 8 秒 | 提供"了解详情"链接 |
| `error` | `ToastItem`（红） | 页面右上角 Toast | 不自动关闭 | 需手动关闭，提供"重试"按钮 |

### 10.2 通知场景映射

| 场景 | 通知类型 | 内容 | Action |
|------|---------|------|--------|
| 方案生成完成 | `success` | "大理3日游方案已生成" | 查看详情 → 跳转 `/plans/:planId` |
| 方案修改完成 | `success` | "行程已调整" | — |
| 方案生成失败 | `error` | "方案生成失败" | 重试 → 重新触发生成 |
| 偏好保存成功 | `success` | "偏好已保存" | — |
| 偏好保存失败 | `warning` | "偏好保存失败，将在网络恢复后重试" | — |
| SSE 断连 | `warning` | "连接已断开，正在重连..." | — |
| SSE 重连失败 | `error` | "连接已断开，请刷新页面" | 刷新页面 |
| 导出完成 | `success` | "文件已准备好，开始下载" | — |
| 导出失败 | `error` | "导出失败，请稍后重试" | 重试 |
| 分享链接已生成 | `success` | "分享链接已复制到剪贴板" | — |
| 网络离线 | `warning` | "网络已断开，部分功能不可用" | — |
| 网络恢复 | `info` | "网络已恢复" | — |

### 10.3 全局 Loading

- 页面级路由跳转 → `uiStore.globalLoading = true`（显示全屏 loading 遮盖）
- 异步任务（生成/修改/导出）→ 使用组件级 loading，不下沉到全局
