# SSE 前后端对比测试报告

> **测试日期**: 2026-07-09  
> **测试工具**: `frontend/src/test/sse_comparison_test.py`  
> **后端状态**: 运行中 (localhost:8000)  
> **测试问题**: 3 个场景（规划类、闲聊类、打招呼）

---

## 一、测试方法

### 方式 A: 模拟前端会话
1. POST `/auth/sessions` → 获取 JWT Token
2. POST `/chat/sessions` → 创建会话
3. POST `/chat/sessions/{id}/messages` → 获取 SSE 流
4. 按 `chatStore.handleSSEEvent()` 逻辑解析 SSE 事件（step_start/message/progress/step_end/done）
5. 检查每条消息是否能被前端组件完全渲染

### 方式 B: 直接后端调用
两种方式本质上使用**同一个 API 端点** (`POST /chat/sessions/{id}/messages`)，返回同一份 SSE 流。区别在于：
- **方式 A** 模拟前端事件分发逻辑，按消息类型构建前端消息列表
- **方式 B** 直接读取原始 SSE 流

**结论**: 前后端原始数据流完全一致，差异仅在前端如何解析渲染。

## 四、前端渲染能力验证

### 4.1 SSE 事件 → 前端组件映射

| SSE 事件 | 前端处理逻辑 (chatStore.ts) | 渲染组件 | 状态 |
|----------|---------------------------|---------|------|
| `step_start` | 创建 `plan_progress` 消息 | `ChatMessage.vue` (进度条) | ✅ |
| `message` | 创建 assistant text 消息 | `ChatMessage.vue` (markdown) | ✅ |
| `progress` | 更新最后一条进度的 content/percent | `ChatMessage.vue` (进度条) | ✅ |
| `step_end` | 标记对应 step 为 completed | 无 UI 变化，内部状态 | ✅ |
| `error` | 创建 error 类型消息 | `ChatMessage.vue` (错误样式) | ✅ |
| `done` (waiting_input) | 什么都不做（流正常结束） | 无操作 | ✅ |
| `done` (方案完成) | 创建 plan_result + 同步 planStore | `PlanPreview.vue` + `PlanDetailPage.vue` | ✅ |

### 4.2 planStore 同步验证

`done` 事件触发后，前端同步更新 `planStore.currentPlan`：
- `id` → `doneData.plan_id` ✅
- `destination` → `summary.destination` ✅
- `days` → `summary.days` ✅
- `total_budget` → `summary.budget.total_budget` ✅
- `estimated_cost` → `summary.budget.actual_total` ✅
- `daily_itinerary` → `summary.daily_itinerary` ✅

## 五、发现的问题

| # | 问题 | 严重度 | 说明 |
|---|------|--------|------|
| 1 | **UI 标签国际化** | 低 | SSE 中 pipeline label 是英文（"Extracting...", "Planning..."），但前端等待提示词是中文混合，显示不够一致 |
| 2 | **方案文本生成逻辑** | 低 | `chatStore.ts` lines 385-401 访问 `daily_itinerary[].attractions`，但后端返的是 `daily_plan[].attractions`，有字段名不匹配风险 |
| 3 | **无实时 token 流** | 中 | message 事件一次性发送完整回复而非逐 token 流式，用户体验不如流式呈现 |
