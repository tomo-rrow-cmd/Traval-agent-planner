# 项目优先级清单

| 优先级 | 模块名称 | 理由/目标 | 关键任务/依据 |
| --- | --- | --- | --- |
| P0 | 多智能体核心编排 (Orchestrator) | 系统的“大脑”，V1.0的灵魂，确保能生成结构化方案而非单纯聊天 | 文档第四章；负责将用户需求拆解并分发给各智能体 |
| P0 | 基础数据闭环 (Data Service) | 提供地理位置、路径规划及景点餐厅数据，是方案生成的基础；优先确保武汉及周边数据准确 | 文档第三章3.5节 & 第五章；打通高德地图API及本地生活数据（大众点评/美团） |
| P0 | 方案生成与展示 (Plan Service) | 用户最终看到的“交付物”，需支持导出或分享，保证基础可用性 | 文档第二章2.2节 & 第六章6.3.2节；生成包含天数、景点、餐饮、住宿的详细行程单 |
| P1 | 路线优化算法 (Route Optimization) | 解决P0阶段简单罗列的问题，确保路线不走回头路、时间安排合理，提升“智能”感知 | 文档4.6.8节；引入TSP等算法优化游览顺序 |
| P1 | 天气适配模块 (Weather Adaptation) | 针对不同时段天气特点，结合天气预报，规划旅游目的地和游览路线 | 文档4.6.6节；根据天气动态调整室内外景点比例 |
| P1 | 前端交互体验 (Frontend UX) | 提升方案的美观度和可读性，让用户直观理解行程安排 | 文档3.4节；实现地图可视化（绘制行程点）和时间轴展示 |
| P1 | 目的地盲盒/目的地选择测试 | 通过随机推荐或趣味测试降低用户决策成本，增加产品趣味性和用户粘性，解决用户"去哪玩"的初始痛点。 | 随机推荐或测试题辅助决策 |
| P2 | 预订与支付系统 (Booking & Payment) | 实现从规划到交易的闭环；因合规及技术复杂度高，延后实施 | 文档第十二章12.2 & 12.3节；对接OTA接口（携程、飞猪等） |
| P2 | 全流程自动化执行 | 从“规划工具”转变为“一站式服务平台”，需要强大的后端调度和第三方支持，属长期目标 | 文档1.2节；实现自动抢票、订酒店、行程中实时提醒 |
