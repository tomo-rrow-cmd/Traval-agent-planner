## 七、关键决策与经验

1. **合并后 CI 门禁逐轮修复策略**：合并大分支后 npm ci、lint、typecheck 三个门禁通常不会一轮全过。今天的修复顺序是 `npm ci → lint → typecheck`，先确保依赖安装成功，再修语法错误，最后修类型错误——这是一个自底向上的有效修复顺序。

2. **`package-lock.json` 不匹配的根因**：合并时 lockfile 可能与任一父分支的 `package.json` 都不匹配。解决方案是直接 `npm install` 重新生成，再逐轮补充缺失的传递依赖（如 `util-deprecate`）。遇到 lockfile 问题时，重新生成比手动合并更可靠。

3. **vue-tsc 类型检查修复链**：`@vue/tsconfig` 缺失 → `skipLibCheck` 未开启 → 类型定义缺失 → 导入路径错误 → ContentBlock 类型滞后——五个问题叠加导致类型检查报错。其中 `@vue/tsconfig` 缺失是最隐蔽的（tsconfig extends 引用但 npm 未安装），报错信息不直接指向根因。

4. **ContentBlock 类型滞后问题**：后端模板新增了 `highlights`、`section`、`divider` 三种 block 类型，但前端 TypeScript 联合类型未同步更新。这暴露了前后端类型契约缺乏自动化校验——后续可考虑从后端 Schema 自动生成前端类型。

5. **环境变量统一到根 `.env`**：Vite 的 `envDir` 可以指向仓库根目录，使前端环境变量与后端 `.env` 共享同一文件，避免 `VITE_AMAP_KEY` 在两处分别配置导致不一致。这个模式值得延续到其他共享配置。

6. **文档债集中清理**：今日 7 个文档 commits 一次性解决了架构文档全面过时、Agent 数量/表数量/管线流程与实际代码不符、空目录残留、断链、过时副本等多个文档债问题。文档同步应作为每个 sprint 结束时的固定环节，而非积压到后期集中处理。

7. **AI 日志纳入版本管理**：新增 `ai-logs/` 目录收录 Sprint 反思报告和 AI 使用日常记录，使得 AI 辅助开发的过程可追溯。配合 `.gitignore` 忽略 `.claude/`（个人工作目录），在团队共享与个人隐私之间取得平衡。
