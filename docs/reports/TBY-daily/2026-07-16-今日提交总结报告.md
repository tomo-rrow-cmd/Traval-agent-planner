## 七、关键决策与经验

1. **大版本迭代的分层提交策略**：晚间 20:41–20:52 的 10 个提交按 DB → Agent → Orchestrator → API → Service → Frontend → Tests → Docs → Config → .gitignore 的顺序依次提交，每层一个 commit，便于代码 review 和问题回溯。这种"自底向上"的提交顺序（从数据层到展示层）值得延续。

2. **`dependencies: []` 阻断 artifact 传递**：GitLab CI 默认将上游 stage 的所有 artifacts 传递给下游 job，即使 job 完全不需要。为 `frontend:build` 和 `docker_image` 添加空的 `dependencies: []` 可显著减少 CI 耗时和存储开销。

3. **exporter big_traffic 完全遗漏**：`export_markdown` 函数之前完全忽略了 `big_traffic` 数据结构的渲染，导致导出的 markdown 缺失往返交通章节。这是一个"数据结构已就绪但展示层遗漏"的典型案例——数据层变更后需要逐层检查到最终展示端。

4. **Node.js v26 breaking change**：Node.js v22.14+ 将 `globalThis.localStorage` 预定义为 `undefined`（只读不可配置），导致 happy-dom 的 `Object.defineProperty` 覆盖失效。解决方案是在 Vitest setup 文件中提前注入 polyfill。这提醒我们关注运行时版本升级可能引入的微妙兼容性问题。

5. **mock 维护成本与代码演进同步**：今日 16 个后端测试修复和 Vitest 测试修正全部是测试代码过时、非业务逻辑 bug——Fake 类缺少新参数、MagicMock 缺少新属性、断言匹配旧输出格式。随着业务代码快速迭代，mock 基础设施的同步维护是一个持续成本，后续可考虑引入契约测试或集成测试来降低对 mock 精度的依赖。

6. **ESLint flat config 迁移**：从旧 `.eslintrc` 格式迁移到 flat config（`eslint.config.js`），同时引入 TypeScript 和 Vue 3 SFC 的专属规则插件。新的 flat config 格式是 ESLint 9.x 的推荐方向，类型推导更好、配置组合更灵活。

7. **覆盖率从 85% 回落至 84% 的快速修复**：大规模功能新增（数据库迁移、5 个 Agent、服务层、API 层、前端）后覆盖率自然回落，通过 `test_ci_coverage.py` 集中补覆盖 + exporter 测试数据丰富化两个手段快速拉回 84%。这种"先冲高、新增代码后回补"的策略在前一天（07-15）的测试强化挑战中已验证有效。
