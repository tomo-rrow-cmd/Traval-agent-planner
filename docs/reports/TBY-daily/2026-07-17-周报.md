**四、 遇到的问题与困难**

*   **技术问题：**
    *   **GitLab CI Shell Executor 稳定性**：Shell executor 复用同一工作目录但不清理 untracked 文件，导致 checkout 失败、Git 锁冲突、Gitaly shallow fetch 服务端 Bug 等多个连锁问题。经过 9 轮修复（GIT_DEPTH=0、GIT_CLEAN_FLAGS、rm -rf 手动清理、禁止双实例并发）才稳定
    *   **Node.js v26 兼容性**：Vitest 在 Node.js v26 下 `localStorage` 未定义，需在 `vitest.config.ts` 中通过 `globalSetup` 注入 polyfill
    *   **前后端字段名不一致**：SSE summary / PlanResponse / 数据库 三层存在多处命名差异（`daily_plan` vs `daily_itinerary`、`hotel` vs `accommodation` 等），前端通过 `normalizeSSESummary` + `mapSSESummaryToPlan` 双函数做了双向兼容映射
    *   **高德 API 配额泄漏**：`test_weather_agent` 每次 CI 运行消耗真实天气 API 配额，通过标记为 `@pytest.mark.integration` 解决
    *   **已尝试的解决方案：** 逐轮 CI 日志排查、curl 独立验证后端、阅读 axios/vitest/vue-tsc 源码确认行为
    *   **需要帮助或待解决：** GitLab 远端认证问题

*   **非技术问题：**
    *   本周继续单兵作战，前后端 + DevOps + 测试 + 文档四条线并行，时间分配上偶尔有顾此失彼的情况。通过日报制度帮助每天复盘，确保不遗漏关键任务。
    *   文档体量膨胀后维护成本显著增加——数据库文档从 200 行膨胀到 280+ 行、代码结构快照覆盖 300+ 文件。后续需要更明确的文档分层（索引入口 vs 详细正文）来降低维护负担，本周的 decisions 索引化就是一个好的方向。
