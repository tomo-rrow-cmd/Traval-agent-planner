## 七、关键决策与经验

1. **纯函数优先策略**：覆盖率从 62% 起步时，先从零外部依赖的纯函数模块入手（validator、context、_dynamic、_two_opt 等），快速积累前 15 个百分点，建立信心后再写 mock 测试。

2. **Mock 分层递进**：ScriptedLLM（控制 LLM 输出）→ monkeypatch（替换外部服务）→ FakeXxx 类（模拟 Repository）→ FastAPI dependency_overrides（模拟 API 依赖注入），按复杂度逐级推进。

3. **覆盖率边际递减**：前 70% 较为顺利，70%→80% 需要大量 mock 基础设施，80%→85% 每个百分点需 10+ 个精准测试，最后 0.13%（3 行）几乎耗尽所有可测试目标。

4. **`builtins.__import__` 全局副作用**：一次失败的 exporter 测试用了 `monkeypatch.setattr("builtins.__import__", ...)` + `importlib.reload`，导致 session 内所有后续 `import` 递归爆栈。教训：绝不全局替换 `builtins.__import__`，改用模块级 monkeypatch。

5. **高德 API 配额异常**：`test_weather_agent` 未标记 `@pytest.mark.integration`，每次 `pytest` 都调用真实天气 API，半天耗尽配额。教训：任何调用外部付费/限流 API 的测试必须标记 `integration`。

6. **远端代码的静态方法调用 bug**：合并时远端 refactoring 将方法改为 `@staticmethod` 但保留了 `self.xxx()` 调用，Python 不会在 import 时报错，只在运行时报 `NameError`。需要有测试覆盖这些路径才能暴露。
