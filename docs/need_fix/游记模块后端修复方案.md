## 1. 缺少 DELETE 端点

### 问题

目前没有 `DELETE /travelogues/{id}` 接口，用户无法删除游记。

### 涉及文件

- `app/api/v1/travelogue.py`
- `app/services/application/travelogue_service.py`
- `app/db/repositories/travelogue_repo.py`

### 修改方案

**① Repository 层** — `app/db/repositories/travelogue_repo.py`

```python
# 在 TravelogueRepository 类中添加
async def delete_by_id(self, travelogue_id: str) -> bool:
    t = await self.get_by_id(travelogue_id)
    if not t:
        return False
    return await self.delete(t)
```

BaseRepository 需确保存在 `delete()` 方法（若没有则添加）：

```python
async def delete(self, obj: T) -> bool:
    await self.db.delete(obj)
    await self.db.commit()
    return True
```

**② Service 层** — `app/services/application/travelogue_service.py`

```python
async def delete(self, travelogue_id: str) -> bool:
    # 可选：校验游记属于当前用户
    return await self.travelogue_repo.delete_by_id(travelogue_id)

async def delete_by_user(self, travelogue_id: str, user_id: str) -> bool:
    """带用户校验的删除"""
    t = await self.travelogue_repo.get_by_id(travelogue_id)
    if not t:
        raise ValueError("游记不存在")
    if t.user_id != user_id:
        raise PermissionError("无权删除该游记")
    return await self.travelogue_repo.delete(t)
```

**③ API 层** — `app/api/v1/travelogue.py`

```python
@router.delete("/{travelogue_id}", response_model=BaseResponse[EmptyData])
async def delete_travelogue(
    travelogue_id: str,
    current_user: dict = Depends(get_current_user),
    service: TravelogueService = Depends(get_travelogue_service),
):
    """删除游记"""
    try:
        await service.delete_by_user(travelogue_id, current_user["user_id"])
        return BaseResponse(data=EmptyData())
    except ValueError as e:
        return BaseResponse(code=404, message=str(e), data=EmptyData())
    except PermissionError as e:
        return BaseResponse(code=403, message=str(e), data=EmptyData())
```

**注意事项：** 级联删除 — `SocialMaterial` 和 `Share` 表通过 trip_id 关联，删除游记本身不级联删除素材和分享，素材可复用于其他用途。如果确实想级联清理，可在 service 层先查并删除关联素材。

## 2. Agent 错误处理与回退策略

### 问题

`TravelogueAgent` 中多处 LLM 调用只有顶层 try/catch，细粒度不足：

- `generate()` 对整段 LLM 调用无捕获 → 某天内容生成失败就整体失败
- `generate_social_materials()` 若单个素材生成失败 → 全部素材丢失
- `_annotate_with_vision()` 失败后静默跳过，但未降级尝试纯文本标注

### 涉及文件

- `app/agents/travelogue_agent.py`

### 修改方案

**① 逐天粒度容错**

`generate()` 方法改为逐天捕获异常，单天失败不阻塞整体：

```python
# 修改前：await self._generate_day_content(...) 无捕获
# 修改后：
for day in sorted(by_day.keys()):
    try:
        content = await self._generate_day_content(...)
    except Exception as e:
        print(f"  [TravelogueAgent] Day {day} 生成失败: {e}, 使用兜底内容")
        content = self._fallback_day_content(day, day_checkins, destination)
    day_contents.append({...})
```

**② 单素材独立容错**

`generate_social_materials()` 中每个素材生成独立 try/catch：

```python
for day in sorted(by_day.keys()):
    try:
        grid9 = await self.photo_organizer.generate_daily_9grid(...)
        if grid9:
            materials.append(grid9)
    except Exception as e:
        print(f"  [TravelogueAgent] Day {day} 9宫格生成失败: {e}")

    try:
        card = await self.photo_organizer.generate_travel_card(...)
        if card:
            materials.append(card)
    except Exception as e:
        print(f"  [TravelogueAgent] Day {day} 卡片生成失败: {e}")
```

**③ Vision 降级链路加固**

`_annotate_with_vision()` 在 Vision 调用失败后，当前逻辑是调用 `_ai_caption_text` 兜底，但判断条件可能因异常提前返回。确保逻辑：

```python

        photo["aesthetic_score"] = result.get("aesthetic_score", 4.0)
        photo["quality_score"] = photo["aesthetic_score"]
    except Exception as e:
        print(f"  [PhotoOrganizer] Vision 标注失败: {e}")
        # 降级 — 已由调用方 process_checkin_photos 中的兜底代码处理
```

确认 `process_checkin_photos` 中的兜底逻辑（第289-295行）在 Vision 失败后正确触发：检查 `p.get("ai_caption")` 是否为 falsy。

**④ 新增超时控制**

LLM 调用增加超时参数，避免单次调用挂起：

```python
# 在 BaseAgent 或 TravelogueAgent 中
async def call_llm(self, messages, temperature=0.7, timeout=30):
    try:
        return await asyncio.wait_for(
            super().call_llm(messages, temperature=temperature),
            timeout=timeout
        )
    except asyncio.TimeoutError:
        logger.warning(f"LLM call timed out after {timeout}s")
        raise
```

## 3. API 缺乏统一错误返回

### 问题

Service 层抛出 `ValueError` / `PermissionError` 时，当前 API 层面没有统一捕获，可能返回 500。

### 涉及文件

- `app/api/v1/travelogue.py`

### 修改方案

在 travelogue router 上注册异常处理器，或每个端点统一 try/catch：

```python
# 方案 A：注册 router 级异常处理器
@router.exception_handler(ValueError)
async def value_error_handler(request, exc):
    return JSONResponse(
        status_code=400,
        content=BaseResponse(code=400, message=str(exc), data=None).model_dump(),
    )

# 方案 B（推荐）：在依赖中统一处理
# app/dependencies.py — 添加统一的 service 错误映射
```

推荐方案 B：定义一个通用的 service 调用包装函数，各处复用：

```python
# app/services/application/base.py 或 travelogue_service.py 内
async def safe_call(func, *args, **kwargs):
    """统一包装 service 调用, 将业务异常转为可序列化错误"""
    try:
        return await func(*args, **kwargs)
    except ValueError as e:
        raise HTTPException(status_code=404, detail=str(e))
    except PermissionError as e:
        raise HTTPException(status_code=403, detail=str(e))
```

然后在 API 层调用 `safe_call(service.get, id)` 代替直接调用。

### 当前需处理的端点

| 端点 | 可能的异常 |
|------|-----------|
| `GET /{id}` | 不存在 → 404 |
| `PATCH /{id}` | 不存在 → 404 |
| `POST /{id}/publish` | 不存在 → 404 |
| `POST /materials/{id}/favorite` | 不存在 → 404 |

## 4. 缺失「重新生成段落」REST 端点

### 问题

Agent 层面 `regenerate_section()` 已实现，REST API 中**没有暴露**，前端无法调用局部重写。

### 涉及文件

- `app/api/v1/travelogue.py`
- `app/schemas/travelogue.py`

### 修改方案

**① Schema** — `app/schemas/travelogue.py`

```python
class RegenerateSectionRequest(BaseModel):
    day: int = Field(..., ge=1)
    style: str = Field(default="diary")
    feedback: str | None = Field(default=None, description="用户反馈/修改意见")
```

**② API 端点** — `app/api/v1/travelogue.py`

```python
@router.post("/{travelogue_id}/regenerate", response_model=BaseResponse[TravelogueResponse])
async def regenerate_section(
    travelogue_id: str,
    request: RegenerateSectionRequest,
    current_user: dict = Depends(get_current_user),
    travelogue_service: TravelogueService = Depends(get_travelogue_service),
    trip_service: TripService = Depends(get_trip_service),
):
    """局部重写某天内容"""
    # 1. 获取原游记 → 找出 trip_id
    travelogue = await travelogue_service.get(travelogue_id)
    if not travelogue:
        return BaseResponse(code=404, message="游记不存在", data=None)

    # 2. 拉取签到数据
    checkins_data = await trip_service.list_checkins(travelogue["trip_id"], page_size=100)
    checkins = checkins_data.list if checkins_data else []

    # 3. 按天筛选
    day_checkins = [c for c in checkins
                    if (c.get("source_day", c.get("day", 1))) == request.day]

    # 4. Agent 局部重写
    from app.agents.travelogue_agent import TravelogueAgent
    from app.services.llm.deepseek import DeepSeekLLM
    agent = TravelogueAgent(DeepSeekLLM())
    result = await agent.regenerate_section({
        "day": request.day,
        "checkins": day_checkins,
        "style": request.style,
        "feedback": request.feedback or "",
        "destination": travelogue.get("title", ""),
    })

    # 5. 将新内容替换回游记
    content = travelogue["content"] or ""
    # 替换对应的 Day 段落（简单实现：按 ## Day N 分割替换）
    import re
    pattern = rf"(## Day {request.day}\n\n).*?(?=\n\n## Day |\n\n---|\Z)"
    replacement = rf"\1{result['content']}"
    new_content = re.sub(pattern, replacement, content, flags=re.DOTALL)

    updated = await travelogue_service.update(
        travelogue_id, content=new_content)
    return BaseResponse(data=updated)
```

## 5. 缺失公开游记浏览 API

### 问题

当前 `GET /travelogues` 只查当前用户的游记，没有浏览其他用户已发布游记的能力。

### 涉及文件

- `app/api/v1/travelogue.py`
- `app/services/application/travelogue_service.py`
- `app/db/repositories/travelogue_repo.py`

### 修改方案（V2.1 可选）

**① Repository**

```python
async def list_public(self, offset: int = 0, limit: int = 20) -> Sequence[Travelogue]:
    query = select(Travelogue).where(
        Travelogue.status.in_(["published", "shared"])
    ).order_by(Travelogue.updated_at.desc()).offset(offset).limit(limit)
    result = await self.db.execute(query)
    return result.scalars().all()

async def count_public(self) -> int:
    return await self.count(status="published") + await self.count(status="shared")
```

**② API**

```python
@router.get("/explore", response_model=BaseResponse[PaginatedData[TravelogueResponse]])
async def explore_travelogues(
    page: int = Query(default=1, ge=1),
    page_size: int = Query(default=20, ge=1, le=100),
    service: TravelogueService = Depends(get_travelogue_service),
):
    """发现公开游记"""
    return BaseResponse(data=await service.list_public(page=page, page_size=page_size))
```

## 6. 修复优先级与建议顺序

| 优先级 | 修复项 | 工作量 | 影响面 |
|--------|--------|--------|--------|
| **P0** | DELETE 端点 | 小（1人时） | 用户无法删除数据 |
| **P0** | Agent 错误处理加固 | 中（2人时） | 生成稳定性 |
| **P1** | 统一错误返回 | 小（1人时） | API 健壮性 |
| **P2** | `regenerate_section` 端点 | 中（2人时） | 功能增强 |
| **P3** | 公开游记浏览 | 中（2人时） | V2.1 功能 |

> **建议：** 第1轮做 P0（DELETE + Agent 容错），第2轮做 P1 + P2.
