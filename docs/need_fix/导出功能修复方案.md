# 导出功能修复方案

> 基于 2026-07-13 实际开发中暴露的问题整理

---

## 一、问题概述

导出功能（Markdown / PDF / Image / Docx）在真实对话生成的方案上无法使用。点击导出按钮后，请求发送到 `POST /api/v1/plans/{plan_id}/exports`，后端返回 **404 Not Found**。

### 用户侧表现

| 场景 | 现象 |
|---|---|
| SSE 对话生成的方案 | 导出按钮可见，点击后请求报 404 |
| 测试数据 / 手动创建的方案 | 导出正常（因为 Plan 表中有记录） |
| 刷新页面 | `/plans/detail` URL 无法恢复数据，页面空白 |

---

## 二、根因分析

### 2.1 数据存储断层

系统中有两个独立的数据实体，但导出接口只查了其中一个：

```
SSE 方案生成流程：

用户对话 → run_pipeline() → persist_plan_result()
                                    ↓
                              plan_runs 表 ← 方案存在这里
                              （ConversationPlanRunRecord 实体）

导出接口 export_plan() 调用 plan_service.get_plan()
                                    ↓
                              travel_plans 表 ← 这里查不到
                              （Plan 实体）
                              → 返回 404
```

**两个存储路径：**

| 路径 | 触发方式 | 存储表 | 导出是否可用 |
|---|---|---|---|
| SSE 管道生成 | 用户对话 → AI 自动生成 → `persist_plan_result()` | `plan_runs` | ❌ |
| 手动创建/保存 | `POST /api/v1/plans` → `plan_service.create_plan()` | `travel_plans` | ✅ |

### 2.2 前端 URL 层面

- PlanPreview 导航到方案详情时，当 `plan.id` 为空，fallback 到字面量 `'detail'`
- 前端路由 `/plans/:planId` 将 `detail` 作为 planId 传入
- 导致所有 API 调用都是 `POST /api/v1/plans/detail/exports`
- 后端无论查 Plan 还是 plan_run，都不存在 id 为 `detail` 的记录

### 2.3 缓存污染

- `planStore.persistCurrentPlan()` 将空 id 的方案存入 localStorage
- 页面刷新后 `restoreCachedPlan()` 恢复空 id 方案
- 死循环：空 id → URL fallback 到 `detail` → 导出 404 → 刷新 → 还是空 id

## 三、修复方案

### 3.1 后端修复（核心）

#### 3.1.1 export_plan 支持降级查 plan_run

**文件：** `app/api/v1/plan.py`

```python
# 修改前：只查 Plan 表
@router.post("/{plan_id}/exports")
async def export_plan(plan_id, format, current_user, plan_service):
    plan_resp = await plan_service.get_plan(user_id=current_user["user_id"], plan_id=plan_id)
    plan_data = plan_resp.model_dump()

# 修改后：Plan 表查不到时降级查 plan_run 表
@router.post("/{plan_id}/exports")
async def export_plan(plan_id, format, current_user, plan_service, conversation_service):
    # 1. 优先查 Plan 表
    try:
        plan_resp = await plan_service.get_plan(...)
        plan_data = plan_resp.model_dump()
    except NotFoundException:
        # 2. 降级：从 SSE 生成的 plan_run 中取 summary
        run = await conversation_service.get_plan_run(plan_id)
        if not run:
            raise NotFoundException("方案不存在")
        plan_data = run.summary or {}
```

#### 3.1.2 新增 get_plan_run 仓储方法

**文件：** `app/repositories/conversation.py`

```python
async def get_plan_run(self, plan_run_id: str) -> PlanRun | None:
    result = await self.db.execute(
        select(PlanRun).where(PlanRun.id == plan_run_id)
    )
    return result.scalar_one_or_none()
```

**同时暴露到 Service 层：** `app/services/application/conversation_service.py`

```python
async def get_plan_run(self, plan_run_id: str) -> dict | None:
    async with async_session_factory() as db:
        repo = ConversationRepository(db)
        run = await repo.get_plan_run(plan_run_id)
        if not run:
            return None
        return {
            "id": run.id,
            "summary": run.summary or {},
            "destination": run.destination or "",
            "days": run.days or 0,
        }
```

## 四、前端已实施的客户端导出方案（不依赖后端）

### Markdown 格式：纯前端生成

`generateClientMarkdown(plan)` 函数从 `planStore.currentPlan` 提取：

- **标题与路线**：方案名称、出发地→目的地、天数
- **行程亮点**：从 `overview.highlights` 取
- **每日行程**：`daily_itinerary` 逐日渲染
  - 景点：名称、描述、时长、价格、评分、提示
  - 餐饮：餐厅、人均价格、推荐理由
  - 住宿：酒店名、价格、地址
- **预算**：`budget` / `budget_detail` 的分项表格
- **出行建议**：`tips` 列表
- **避坑提醒**：`avoid_list` 列表

生成后直接用 `Blob` + `URL.createObjectURL` 触发下载，全程无网络请求。

**适用范围：** 所有方案（包括未保存到后端的 SSE 方案）

## 六、未解决问题 / 后续优化

| 问题 | 优先级 | 建议方案 |
|---|---|---|
| 后端导出 PDF/Image/Docx 为异步任务，前端没有轮询下载进度的机制 | 低 | 前端加 `pollExportTask(taskId)` 轮询 |
| SSE 方案自动保存到 Plan 表的功能缺失 | 中 | `persist_plan_result` 调用后同步创建 Plan 记录 |
| 方案详情页查看时，同时接受 SSE 流式更新可能导致状态冲突 | 低 | Pinia store 加乐观锁 / 版本号 |
| 无网络环境下导出不可用（PDF/Image/Docx） | 低 | 前端引入 `html2canvas` + `jsPDF` 做纯客户端导出 |
